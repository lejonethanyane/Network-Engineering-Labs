## Network Engineering Methodology

Each project follows a structured workflow similar to the processes used by network engineering teams in enterprise environments.

### 1. Business Requirements and Planning

Before building a network, I establish:

- Business requirements and objectives
- Number of users, departments, and devices
- Connectivity and network service requirements
- Security and network segmentation needs
- Scalability, availability, and redundancy requirements
- Technical constraints and assumptions

### 2. Network Design

I develop the network design before starting any configurations.

This includes:

- Network topology diagrams
- Device selection and network architecture
- IP addressing and subnetting plans
- VLAN and routing design
- Security considerations
- Redundancy and availability planning

### 3. Method of Procedure (MOP)

Before implementing changes, I prepare a Method of Procedure documenting:

- Change objective and scope
- Prerequisites
- Expected impact and risks
- Pre-implementation checks
- Reviewed configuration commands
- Implementation sequence
- Verification and success criteria
- Rollback procedures

This encourages controlled implementation and reduces the risk of configuration errors.

### 4. Pre-Implementation Checks

Before making configuration changes, I verify the existing network state.

Typical checks include:

- Interface status
- IP addressing
- VLAN assignments
- Trunk configurations
- Routing tables
- Existing connectivity
- Current device configurations

### 5. Controlled Implementation

Network changes are implemented according to the documented MOP.

Configuration commands are prepared and reviewed before execution.

Unexpected behaviour is investigated rather than making unplanned changes without understanding their impact.

### 6. Post-Implementation Verification

After implementation, I perform verification tests to confirm that the network meets its design requirements.

These may include:

- Ping and traceroute testing
- Routing table verification
- VLAN and trunk verification
- End-to-end connectivity testing
- Redundancy and failover testing
- Security configuration validation

### 7. Troubleshooting and Root Cause Analysis

Where network failures occur, I use a structured troubleshooting process:

1. Identify the reported problem.
2. Gather information and establish symptoms.
3. Determine the scope of the failure.
4. Investigate potential causes.
5. Identify the root cause.
6. Implement a corrective action.
7. Verify service restoration.
8. Document findings and lessons learned.

## Project Documentation Standards

Each completed project will aim to contain:

1. **Business Scenario** — The business requirements and problem being addressed.
2. **Network Design Document** — Architecture, topology, IP addressing, and design decisions.
3. **Method of Procedure (MOP)** — Implementation plan, risks, and rollback steps.
4. **Pre-Implementation Checks** — Network baseline and readiness verification.
5. **Configuration Files** — Cisco IOS commands used during implementation.
6. **Implementation Record** — Changes performed and observations.
7. **Post-Implementation Tests** — Connectivity and functionality verification.
8. **Troubleshooting Report** — Root cause, investigation, and corrective actions where applicable.
9. **Evidence** — Screenshots, command outputs, and test results.
10. **Lessons Learned** — Key technical findings and improvements.
